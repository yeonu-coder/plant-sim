# 🌱 마이플랜테리어

**배포 주소:** https://yeonu-coder.github.io/plant-sim/

## 1. 프로젝트 목적과 대상 사용자

식물을 처음 키우는 사람은 "우리 집에 어떤 식물이 맞을까?"부터 막막합니다. 마이플랜테리어는 이런 **초보 식집사**를 위한 식물 추천 웹사이트입니다.

사용자는 가상의 새싹을 키우는 게임을 하면서 7가지 질문에 답합니다. 물을 얼마나 자주 챙길 수 있는지, 햇빛·온도·습도, 집을 비우는 빈도, 반려동물, 둘 공간을 묻습니다. 답이 끝나면 생활 패턴과 집 환경에 맞는 식물 3가지를 추천 이유와 함께 보여 줍니다. 마음에 드는 식물은 가상의 꽃집에서 (시연용으로) 주문하고 도감에 모을 수 있습니다.

## 2. 사용 방법

- **인터넷:** 위 배포 주소로 접속합니다.
- **내 컴퓨터:** 저장소를 내려받아 `index.html`을 더블클릭합니다. 설치할 것은 없습니다.
- **화면 흐름:** 경험 수준 선택 → 새싹 키우기 질문 7개 → 추천 3종 → 상세보기 → 꽃집 선택·주문 → 도감(5종·10종 배지)
- **데이터 변환 스크립트(선택):** 농사로 CSV 원본은 저장소에 없으므로, 아래 "데이터 출처"에서 받아 `data/plants_nongsaro.csv`(cp949)로 저장한 뒤 실행합니다.

```bash
python3 scripts/convert_nongsaro.py --check   # 데이터 점검만 (파일을 고치지 않음)
python3 scripts/convert_nongsaro.py           # 점검 후 js/data/plants.js 조건값 갱신
```

## 3. 작업 과정 요약

1. **기획:** 화면 흐름, 데이터 형식, 추천 규칙, 작업 순서를 `CLAUDE.md`에 설계도로 먼저 정리했습니다.
2. **1~4단계:** 시작 화면, 식물 20종 데이터, 새싹 게임, 추천 계산과 결과 화면을 한 단계씩 만들고 확인했습니다.
3. **공공데이터 변환과 규칙 보완:** 농사로 데이터로 15종의 조건값을 바꾸는 스크립트를 만들고, 비교 결과를 보며 규칙을 고쳤습니다.
4. **손 검산:** 한 상황의 추천 점수를 손으로 계산해 코드와 맞춰 봤습니다.
5. **5~7단계:** 상세보기, 구매·주문 완료, 도감과 배지를 만들었습니다.
6. **배포:** GitHub Pages에 올렸습니다.
7. **휴대폰 테스트 수정:** 실제 휴대폰에서 써 보며 게임 조작, 여백, 캐시 문제를 고쳤습니다.

## 4. Claude Code 작업 증거와 검증 결과

| # | 무엇을 | 결과 |
|---|---|---|
| 1 | 반려동물 안전 식물 수 | Claude Code가 표에 "안전 7종"이라고 적었지만, 다시 세어 보니 **8종**이어서 정정했습니다. (이후 식물 2종 교체로 지금은 10종) |
| 2 | 공공데이터 변환 후 비교 | "온도 기준이 서로 달라요"를 발견했습니다. AI 초안은 견딜 수 있는 넓은 범위, 농사로는 잘 자라는 좁은 범위였습니다. → **온도 여유 3℃**, **물 주기 4단계**(1·3·7·14일) 규칙을 추가했습니다. |
| 3 | 손 검산 | 상황 A(그늘·건조·거의 못 챙김·입문자)에서 하월시아 **손 계산 85점 = 코드 85점**. 2·3위도 일치했습니다. → [docs/hand-check.md](docs/hand-check.md) |
| 4 | 스크립트 재실행 | 변환 스크립트를 두 번 돌려도 `plants.js` 결과가 **똑같았습니다**(파일 해시 동일). |
| 5 | 엣지 케이스 | 깨진 localStorage 값(`{깨짐` 등)을 넣어도 멈추지 않고 **빈 도감**으로 시작했습니다. 같은 식물을 다시 주문해도 **중복 저장되지 않았습니다**. |
| 6 | 배포 미반영 | 멈춘 Pages 배포 하나 때문에 이후 배포가 "진행 중인 배포가 있음"으로 거절된 것을 로그에서 찾았습니다. → 정리 후 **재배포**했습니다. |

## 5. 효과적이었던 방법

1. **설계도를 먼저, 확인은 한 단계씩.** `CLAUDE.md`에 규칙을 정해 두고 단계마다 브라우저로 확인한 뒤 커밋했습니다. 문제가 생겨도 어느 단계에서 생겼는지 바로 알 수 있었습니다.
2. **표로 받아서 직접 검토.** 식물 데이터와 추천 결과를 표로 받아 보니, 반려동물 집에 추천할 식물이 부족한 점이나 온도 기준 차이가 눈에 띄었습니다.
3. **계산은 스크립트, 확인은 사람.** 변환은 스크립트로 반복 가능하게 하고, 맞는지는 손 검산과 실제 휴대폰으로 제가 확인했습니다.

## 6. 어려웠던 점과 대응

1. **공공데이터와 AI 초안의 기준 불일치.** 온도 범위의 뜻이 달라 같은 방 온도에서 점수가 크게 갈렸습니다. 온도 여유와 물 주기 4단계 규칙을 만들고, 바꾼 이유를 [docs/data-rules.md](docs/data-rules.md)에 기록했습니다. *남은 문제:* 산세베리아·금전수는 물을 아주 드물게 줘도 되지만, 농사로 원문이 "토양 표면이 말랐을 때"라서 7일로 계산됩니다. 원문을 우선하기로 했습니다.
2. **휴대폰에서만 생긴 문제.** PC에서는 괜찮았지만 휴대폰에서는 누른 자리에 hover 테두리가 남았고, 선택지를 누르면 바로 넘어갔고, ← 버튼이 헷갈렸습니다. hover는 마우스 기기에서만 보이게 하고, "고르기 → [다음]" 방식과 아래쪽 [이전]/[다음] 버튼으로 바꿨습니다.
3. **배포 미반영과 휴대폰 캐시.** 배포가 거절돼 예전 화면이 나왔고, 카카오톡 브라우저는 예전 CSS·JS를 계속 썼습니다. 배포 로그로 원인을 찾아 재배포하고, 파일 주소에 버전 번호(`?v=`)를 붙였습니다.

## 7. 알려진 한계

- 20종 중 **5종**(로즈마리, 알로에 베라, 에케베리아, 하월시아, 올리브나무)은 공공데이터에 없어 AI 초안 값입니다.
- 물 주기 일수는 원문 문장을 바꾼 **근사값**이고, 겨울 물 주기는 상세보기에만 보이며 점수에는 반영하지 않습니다.
- 꽃말은 3종만 채웠고, 수명은 대부분 확인하지 못했습니다(화면에 "확인 중"·"AI 초안" 표시).
- 식물 사진 대신 이모지를 씁니다.
- 꽃집, 가격, 주문은 모두 **시연용**이며 실제 결제가 없습니다.
- 도감은 브라우저(localStorage)에만 저장되어 다른 기기나 브라우저에서는 보이지 않습니다.

## 8. 채점용 핵심 파일

| 파일 | 설명 |
|---|---|
| `js/recommend.js` | 답변과 식물 조건을 비교해 점수를 매기고, 상위 3종과 카드별 추천 이유를 고릅니다. |
| `js/app.js` | 화면 전환과 게임·결과·상세보기·구매·도감 화면의 동작을 담당합니다. |
| `js/storage.js` | 도감과 배지를 localStorage에 저장하고, 깨진 값은 걸러 냅니다. |
| `js/data/plants.js` | 식물 20종 데이터와 항목별 출처(농사로 / AI 초안) 정보입니다. |
| `scripts/convert_nongsaro.py` | 농사로 CSV를 점검하고 식물 조건값으로 변환합니다. |

## 9. 데이터 출처

- **농촌진흥청 농사로 「실내정원용 식물」 Open API 데이터** (2024.07.16 수집)
  - 2024년 해커톤 참여 당시 확보한 데이터를 이번 프로젝트에 맞게 재가공했습니다.
  - 출처: 농사로 누리집 https://www.nongsaro.go.kr (Open API 「실내정원용 식물」)
- 20종 중 **15종**은 이 데이터에서 빛, 물 주기, 온도, 습도, 난이도, 크기를 가져왔습니다.
- 원본 CSV는 재배포 조건을 확인하지 못해 **저장소에 올리지 않았습니다.**
- 식물마다 `source`(출처)가 있고, 상세보기에서 항목별로 나눠 보여 줍니다.
  - "농사로 공공데이터" 15종: 위 조건값은 스크립트가 만들고 손으로 고치지 않습니다. 단, 수명·반려동물 안전 여부·꽃말은 CSV에 없어 AI 초안입니다.
  - "AI 초안" 5종: 화면에 **"AI 초안 정보"** 표시가 붙습니다.
  - CSV 값이 비어 AI 초안으로 남은 항목은 `draftFields`에, 다른 이름·품종의 값을 쓴 경우는 `sourceNote`에 적었습니다(예: 고무나무 → "데코라고무나무 값 사용").
  - 확실하지 않은 정보는 지어내지 않고 `null`로 두어 "확인 중"으로 표시합니다.
- 자세한 규칙: [docs/data-rules.md](docs/data-rules.md) · 손 검산: [docs/hand-check.md](docs/hand-check.md)

## 10. AI 도구 사용 범위

이 프로젝트는 **Claude Code**(AI 코딩 도구)를 사용해 개발했습니다.

- **내가 한 것**
  - 기획: 서비스 아이디어, 화면 흐름, 질문 구성, 단계별 작업 순서
  - 데이터 판단: 농사로 데이터 사용, 식물 선정과 교체, 변환 규칙 결정, 한계를 그대로 둘지 결정
  - 검증: 단계마다 브라우저 확인, 추천 점수 손 검산, 비교 상황을 정해 결과 검토, 실제 휴대폰 테스트
- **Claude Code가 한 것**
  - 내 지시에 따라 코드, 변환 스크립트, 문서 초안 작성
  - 자동 브라우저 테스트 실행, 배포 로그 확인
- 출처가 "AI 초안"인 식물 정보는 AI가 만든 초안이라 실제와 다를 수 있어 화면에 표시해 두었습니다.
